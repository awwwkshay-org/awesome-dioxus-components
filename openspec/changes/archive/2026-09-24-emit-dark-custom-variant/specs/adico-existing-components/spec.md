## MODIFIED Requirements

### Requirement: The adico theme provides success, warning, and info semantic tokens
The adico-managed CSS theme region (generated by `packages/adico-cli/src/css.rs` into a consumer's `tailwind.css`) SHALL define `--success`, `--warning`, and `--info` custom properties, each paired with a `-foreground` counterpart, for both the light (`:root`) and dark (`.dark`) theme blocks, alongside the existing `--destructive`/`--destructive-foreground` pair. `ThemeBuilder`'s token editor SHALL expose all six as editable `ThemeToken` entries.

The adico-managed region SHALL also declare the `dark` variant against the
theme class it generates its dark token block for, so that literal `dark:`
utilities and token-driven colours are governed by the same signal. A consumer
SHALL NOT have to declare that variant themselves to make class-based theme
switching apply to `dark:` utilities, and those utilities SHALL NOT follow the
operating system's colour-scheme preference when the consumer has chosen an
appearance explicitly.

#### Scenario: A newly initialized project has the new tokens
- **WHEN** a consumer runs `adico init` (or refreshes their theme install)
- **THEN** their `tailwind.css`'s adico-managed region defines `--success`, `--warning`, `--info` and their `-foreground` pairs in both the light and dark blocks

#### Scenario: A user edits a new tone token in ThemeBuilder
- **WHEN** a user opens `ThemeBuilder` and edits the Success, Warning, or Info token
- **THEN** the edit updates the corresponding CSS custom property live, the same way editing `Destructive` already does

#### Scenario: A consumer's chosen appearance disagrees with their OS
- **WHEN** a consumer's project compiles its stylesheet from the
  adico-managed region, and a user selects an appearance that differs from
  their operating system's colour-scheme preference
- **THEN** elements styled with literal `dark:` utilities render according to
  the appearance the user selected, consistently with every token-driven
  colour on the page

#### Scenario: A consumer does not declare the variant themselves
- **WHEN** a consumer's `tailwind.css` contains only the adico-managed region
  and no hand-written variant declaration
- **THEN** class-based theme switching still governs literal `dark:` utilities
