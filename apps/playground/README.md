# adico playground

Interactive explorer for every component currently migrated into the adico
registry, installed the same way a real consumer would install them: via
`adico add`, not a direct workspace import of `adico-primitives`/`registry`.

## Structure

- `src/pages.rs` — one page component per installed registry item (e.g.
  `ButtonPage`, `DialogPage`).
- `src/main.rs` — the `Route` enum (`dioxus-router`, requires the `router`
  Dioxus feature), a `Layout` with a nav sidebar linking every page, and the
  `Home` landing page.
- `src/demo.rs` — the shared `Demo` wrapper each page uses to render its
  component under a heading.
- `src/components/` — generated by `adico add`; do not hand-edit the
  `// adico:start` / `// adico:end` managed region in `components/mod.rs`.

## Wiring a fresh app for Tailwind (manual today)

`adico init` / `adico add` writes the CSS theme tokens but does **not** yet
wire the following two steps automatically — do them by hand once per app:

1. Add a project-root `tailwind.css` (compile *input*, not the generated
   output) containing at minimum:
   ```css
   @import "tailwindcss";
   @source "./src";
   /* adico:theme:start */
   ...
   /* adico:theme:end */
   ```
   `dx serve`/`dx build` auto-detects this file and compiles it into
   `assets/tailwind.css` (generated output — never hand-edit that file).
2. Link the compiled stylesheet and enable the Dioxus `document` feature:
   ```rust
   const TAILWIND_CSS: Asset = asset!("/assets/tailwind.css");
   // in your root component:
   document::Stylesheet { href: TAILWIND_CSS }
   ```
   ```toml
   dioxus = { version = "=0.7.9", features = ["document", ...] }
   ```

Without both steps, every installed component renders as unstyled semantic
HTML.

## Running

```sh
dx serve --platform web
```
